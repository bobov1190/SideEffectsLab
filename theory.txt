QUESTION 1. What is a side-effect and why not in the composable body?

What is a side-effect?
A side-effect is any change that happens outside of the function itself.

Why is the composable body a dangerous place?
A composable function must only describe the UI from the current state.
It should be "clean": the same input gives the same UI, and nothing else
happens.

So in the example, viewModel.loadProfile() and analytics.log("opened")
run again and again on every animation frame. That is why the requests
and log entries multiply. Worse, some of them can come from an attempt
that was thrown away, so they describe something that never appeared.

Why does data loading belong in the ViewModel (unidirectional data flow)?
In unidirectional data flow, the state goes DOWN and
the events go UP.

QUESTION 3. LaunchedEffect(pulseRateMs) with a while loop

Code:
    LaunchedEffect(pulseRateMs) {
        while (isActive) {
            delay(pulseRateMs)
            alpha.animateTo(0f)
            alpha.animateTo(1f)
        }
    }

When does the effect start?
It starts when the composable enters the Composition (the first time it
is shown). LaunchedEffect starts a coroutine, and the coroutine runs
the block. The loop begins with delay(3000), so the first pulse is
after 3 seconds.

What happens when pulseRateMs changes from 3000 to 1000?
pulseRateMs is the key of the LaunchedEffect. When a key changes,
Compose cancels the old coroutine and launches a NEW one with the new
key. So:
 - the old loop stops (it is cancelled in delay() or animateTo());
 - the new loop starts from the beginning and waits 1000 ms, then pulses.
If the old loop was in the middle of the animation, alpha stays at its
current value, and the new loop continues from there.

What happens to the while loop when the composable leaves the
Composition? What does isActive check?
When the composable leaves the Composition, its coroutine is cancelled
automatically. delay() and animateTo() are suspend functions that check
for cancellation, so they throw a CancellationException and the loop
ends. isActive checks whether the coroutine is still alive
isActive is useful in the loop condition so the loop is not infinite
after cancellation, especially if the loop has some code that is not a
suspend call.

How the lecture's MiniComposition model shows this:
The model imitates the same rule. When the composition is left,
the running effect is cancelled, and it
does not do any more work after that.
